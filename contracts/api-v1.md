# عقد API v1

المسار الأساسي `/api`. الطلبات والاستجابات JSON. رسائل الأخطاء عربية، وأسماء الحقول والرموز ثابتة. لا توجد مصادقة في هذه المرحلة. يولّد الخادم UUID جديداً لكل طلب، ويعيده في `X-Request-ID` وفي جسم الأخطاء؛ لا يُعتمد معرّف يرسله العميل.

## GET /api/health

HTTP 200، مثال بعد بناء الفهرس الحالي:

```json
{
  "status": "degraded",
  "index_ready": true,
  "llm_configured": false,
  "documents_count": 5,
  "chunks_count": 545
}
```

`llm_configured` يدل على وجود مفتاح غير فارغ في الإعدادات فقط، ولا يفحص صحته ولا يتصل بالمزوّد. `index_ready` يصبح `true` بعد تحميل فهرس BM25 صالح ومطابق لبصمات الإدخال والمصادر. يتغير إلى `false` عند غياب الفهرس أو تغيّر مدخلاته؛ يلزم إعادة بنائه. العدادات تخص السجل المحلي الموثوق حتى إذا لم يُبنَ فهرس الاسترجاع بعد. عند غياب سجل صالح تكون صفرية. يبقى `status=degraded` متوافقاً مع مخطط v1 بسبب تغطية المصادر الجزئية؛ الجاهزية التشغيلية ممثلة بالحقول الأخرى.

## POST /api/chat

```json
{
  "question": "السؤال الحالي",
  "history": [
    {"role": "user", "content": "سؤال سابق"},
    {"role": "assistant", "content": "إجابة سابقة"}
  ]
}
```

- `question`: نص مطلوب، من 1 إلى 2000 محرف؛ يُرفض النص المكوّن من مسافات فقط. تُحسب المسافات ضمن الحد.
- `history`: قائمة اختيارية، افتراضياً `[]`، بحد أقصى 8 رسائل سابقة فقط؛ السؤال الحالي مستقل عنها.
- `academic_context`: كائن اختياري أو `null`؛ يبقى الطلب القديم دون هذا الحقل صالحاً. مثال:

```json
{
  "program_id": "computer_engineering",
  "plan_version": "2021-1",
  "completed_course_codes": ["10032100"],
  "user_declared_completed_credits": 75
}
```

سياق الملف مكتوب الأنواع ويرفض الحقول الإضافية؛ لا يتضمن الاسم أو رقم التسجيل أو الكلية الحرة. `program_id` أحد الأهداف الأربعة أدناه، و`plan_version` نسخة متاحة لذلك الهدف. `completed_course_codes` افتراضياً `[]`، بحد 400 إدخال نصي من 7–9 أرقام ASCII، وتزال التكرارات. يتحقق الخادم من عضوية كل رمز في الخطة المحددة؛ الرمز الصحيح شكلياً من خطة أخرى غير مقبول. `user_declared_completed_credits` اختياري أو `null`، رقم محدود من 0 إلى 400، مستقل عن مجموع قائمة المقررات، وليس رصيداً رسمياً. السياق أو العضوية غير الصالحين يعيدان 422 `VALIDATION_ERROR` دون استدعاء المزوّد.

أولوية حل النطاق: التخصص والخطة الصريحان في السؤال الحالي، ثم سياق رسائل المستخدم السابقة، ثم الملف كقيمة افتراضية عند بقاء التخصص غامضاً. لا تُستعار خطة الملف لتخصص مختلف صُرّح به في السؤال، ولا يُستبدل إصدار خطة صريح بإصدار الملف. لا تُستنتج خطة من رقم التسجيل أو سنة الالتحاق. تُرسل اختيارات الإنجاز إلى النموذج فقط إذا طابقت التخصص والخطة المحسومين، تحت `user_declared_context` وخارج `evidence`. هي تصريحات شخصية وليست كشف علامات أو إثبات أهلية تسجيل، ولا توسع الأدلة المعتمدة أو تثبت متطلبات المركبات الناقصة.

- لكل رسالة `role` إما `user` أو `assistant` حصراً، و`content` نص من 1 إلى 4000 محرف، لا يكون مسافات فقط.
- أخطاء النوع أو الحقول المطلوبة أو الأطوال أو JSON غير الصالح تعيد HTTP 422 بالشكل الموحد أدناه.

عند غياب فهرس صالح يعيد الطلب HTTP 503 دون استدعاء النموذج:

```json
{
  "error": {
    "code": "KNOWLEDGE_NOT_READY",
    "message": "لم يتم تجهيز مستندات الجامعة بعد.",
    "request_id": "<UUID يولده الخادم>"
  }
}
```

غياب الفهرس ليس `insufficient_evidence`. عند جاهزية الفهرس تُنفّذ مطابقة رموز المساقات وBM25 مع التخصص ونسخة الخطة. يُطلب توضيح عند الغموض. تستخدم رسائل المستخدم السابقة لتحديد التخصص أو مرجع متابعة فقط، ولا تُرسل كدليل للنموذج.

### الاستجابة

استجابة HTTP 200 تحافظ على الحقول التالية؛ المثال مقتبس من اختبار حي فعلي، مع اختصار معرّف الطلب:

```json
{
  "request_id": "<UUID يولده الخادم>",
  "status": "answered",
  "answer": "وفقاً لخطة 2021-1 لتخصص هندسة الحاسوب، فإن مجموع الساعات المطلوبة هو 162 ساعة معتمدة [S1].",
  "citations": [
    {
      "source_id": "S1",
      "document_id": "zajel_10636_2021_1",
      "title": "هندسة الحاسوب",
      "filename": "computer_engineering_10636_2021_1.htm",
      "page": null,
      "article": "ملخص الخطة ومجموع الساعات المطلوبة",
      "quote": "الخطة: سنة  2021 - فصل 1\nمجموع الساعات المطلوبة:\n162"
    }
  ],
  "latency_ms": 743
}
```

قيم `status`: `answered` للإجابة الموثقة، `insufficient_evidence` لسؤال أكاديمي بلا دليل كافٍ أو عند فشل التحقق من خرج النموذج، `out_of_scope` لسؤال غير أكاديمي ضمن تصنيف محلي محافظ، و`needs_clarification` لغموض المساق أو البرنامج أو المرحلة. تعيد الحالات الثلاث الأخيرة HTTP 200؛ لا يحتاج النقص أو الغموض المعروف مسبقاً اتصالاً بـGroq. متطلبات المركبات الرسمية غير متوفرة، والحقل الفارغ في المصدر لا يعني عدم وجود متطلب.

`latency_ms` عدد صحيح غير سالب. `page` رقم صفحة PDF الفعلي بدءاً من 1، وليس الرقم المطبوع. التوضيح الصريح لمصادر HTML: `page=null` ويحتوي `article` موضع المساق أو القسم؛ لا تُختلق صفحات. لم تتغير حقول استجابة المحادثة؛ سياق الملف إضافة اختيارية للطلب فقط. تُنشأ الاستشهادات على الخادم من الأدلة المرسلة فقط؛ لا تُقبل أسماء ملفات أو اقتباسات أو صفحات يولّدها النموذج. يتحقق الخادم من JSON ومعرّفات المراجع والاستشهاد بكل فقرة والأرقام والحفاظ على تعبيرات المتطلبات؛ هذا لا يضمن انعدام الهلوسة أو التحقق الدلالي الكامل.

السياق المسترجع محدود بستة مقاطع وبميزانية `RAG_CONTEXT_TOKEN_BUDGET` الافتراضية 6000 (512–20000). يُحسب حجم UTF-8 كبَديل محافظ لعدد tokens للأدلة فقط، ويُترك السؤال وتعليمات النظام خارجه. لا توجد embeddings أو قاعدة متجهات. درجات BM25 لترتيب النتائج وليست احتمالات ثقة.

## GET /api/programs

مسار قراءة فقط من الفهرس المحمّل والمتحقق منه؛ لا يستدعي Groq. يعيد `{"programs": [...]}` بأربعة أهداف بالضبط:

| program_id | major_code | نسخة الخطة | صفوف المقررات |
| --- | --- | --- | --- |
| `computer_engineering` | `10636` | `2021-1` | 125 |
| `medicine` | `10702` | `2025-1` | 123 |
| `physical_education` | `11350` | `2025-1` | 64 |
| `vehicle_engineering` | `10624` | `2026-1` | 60 |

لا يظهر برنامج الهندسة الميكانيكية المرجعي كهدف خامس. كل برنامج يحتوي `program_id` و`program_name_ar` و`major_code` و`faculty_name_ar` و`plans`. الكلية `null` ما لم تتوفر بيانات مصدر صريحة؛ لا تُستنتج من اسم البرنامج. لكل خطة:

- `plan_version` و`total_required_credits` من ملخص المصدر، دون جمع خيارات المقررات كلها.
- `credit_groups`: عناصر `{name_ar, required_credits, is_elective}`؛ تُقص المسافات المحيطة بأسماء المجموعات لمطابقة المقررات. `is_elective` يميز مجموعات الاختياري والمساق الحر التي تعرض بدائل.
- `course_count` و`course_coverage` و`is_partial` و`coverage_limitations`: حدود المصدر الفعلية بنص واضح.
- `document_id` و`source_locator`: معرّف المستند المعتمد وموقع المصدر، دون مسارات محلية أو بصمات داخلية.

موقع المصدر يحتوي `page` (`null` لـHTML)، و`section`، وقد يحتوي `article` و`course_code` و`major_code` أو `null` لها. خطة المركبات جزئية: 60 صفاً مطلوباً فقط، وخيارات الاختياري والمتطلبات السابقة الرسمية مفقودة، ولوحة الساعات الحرة المنفصلة غير محسومة. لا تعرض كتغطية تخرج كاملة. عند غياب الفهرس الموثوق يعاد HTTP 503 `CATALOG_UNAVAILABLE`، لا قائمة بديلة تجريبية.

## GET /api/programs/{program_id}/plans/{plan_version}/courses

مسار قراءة فقط؛ يعيد `{program_id, plan, courses}`. `plan` بنفس مخطط ملخص الخطة أعلاه. عناصر `courses` تحتوي:

```json
{
  "course_code": "10032100",
  "course_name_ar": "انجليزي استدراكي",
  "course_name_en": "Remedial English",
  "credits": 0,
  "requirement_group_ar": "إجباري جامعة",
  "document_id": "zajel_10636_2021_1",
  "source_locator": {"page": null, "section": "إجباري جامعة ", "article": "المساق 10032100", "course_code": "10032100", "major_code": null},
  "prerequisite_status": "not_listed_in_source_row",
  "prerequisite_expression_raw": null
}
```

`course_name_en` قد يكون `null`. رموز المقررات ونصوص المتطلبات تأتي من السجلات الأصلية؛ حقل فارغ لا يثبت عدم وجود متطلب. `not_provided_for_this_plan` يميز المتطلبات الرسمية غير المتوفرة لخطة المركبات. تركيبة برنامج/خطة غير معتمدة تعيد 404 `NOT_FOUND`، وغياب الكتالوج يعيد 503 `CATALOG_UNAVAILABLE`.

الواجهة تحفظ الاسم ورقم التسجيل محلياً في `student_profile`، وتحفظ اختيارات الإنجاز بالمفتاح `student_completed_courses:v2:{program_id}:{plan_version}`. لا ترحّل اختيارات العرض التجريبي القديمة إلى أي خطة حقيقية. يُحسب كل رمز مرة واحدة، والمقرر الصفري لا يضيف ساعات. يُعرض مجموع الاختيارات منفصلاً عن الساعات اليدوية؛ الاحتساب الاسترشادي يقيد مساهمة كل مجموعة بساعاتها المطلوبة، ولا يشترط إتمام جميع البدائل ولا يمثل تدقيق تخرج أو أهلية تسجيل رسمية.

## GET /api/documents

HTTP 200، يحتوي كل مصدر على الحقول الموثقة:

```json
{"documents": [{"document_id": "zajel_10636_2021_1", "title": "هندسة الحاسوب", "filename": "computer_engineering_10636_2021_1.htm", "page_count": null}]}
```

`document_id` و`title` و`filename` نصوص. `page_count` عدد صحيح موجب لـPDF، و`null` لـHTML. القائمة الفعلية تضم المصادر الخمسة، وتبقى متاحة من سجل صالح حتى قبل بناء الفهرس. لا تعرض API المسارات المحلية أو بصمات الملفات الداخلية.

## GET /api/documents/{document_id}/file

`document_id` معرّف معتم يُحل فقط عبر السجل الموثوق؛ لا يُحوّل إدخال العميل إلى مسار. تُحصر الملفات في `data/data/raw/` وتُفحص بصماتها عند التحميل والتغيّر. يعاد المصدر كتنزيل `application/octet-stream` مع `Content-Disposition: attachment` و`nosniff` وCSP sandbox، بما في ذلك HTML. المعرّف المجهول أو السجل غير الصالح يعيد 404 `NOT_FOUND`.

## الأخطاء

```json
{
  "error": {
    "code": "ERROR_CODE",
    "message": "رسالة عربية واضحة",
    "request_id": "<UUID يولده الخادم>"
  }
}
```

| HTTP | code | message |
| --- | --- | --- |
| 404 | `NOT_FOUND` | المورد المطلوب غير موجود. |
| 422 | `VALIDATION_ERROR` | بيانات الطلب غير صالحة. راجع الحقول والحدود الموثقة. |
| 503 | `KNOWLEDGE_NOT_READY` | لم يتم تجهيز مستندات الجامعة بعد. |
| 503 | `LLM_NOT_CONFIGURED` | لم يتم إعداد خدمة الإجابة بعد. |
| 503 | `CATALOG_UNAVAILABLE` | كتالوج البرامج والمقررات غير متاح حالياً. أعد المحاولة لاحقاً. |
| 504 | `LLM_TIMEOUT` | انتهت مهلة خدمة الإجابة. حاول لاحقاً. |
| 429 | `LLM_RATE_LIMIT` | بلغت خدمة Groq حد الاستخدام. راجع الحصة المتاحة ومدة التهدئة إن توفرت. |
| 502 | `LLM_UNAVAILABLE` | خدمة الإجابة غير متاحة حالياً. حاول لاحقاً. |
| 405 | `METHOD_NOT_ALLOWED` | طريقة الطلب غير مسموحة. |
| 500 | `INTERNAL_ERROR` | حدث خطأ داخلي. يرجى المحاولة لاحقاً. |

عند تصريح Groq بفئة `RPD` أو `TPD` تبقى الشيفرة `LLM_RATE_LIMIT`، وتصبح الرسالة: «استُنفدت حصة Groq اليومية. يلزم تجدد الحصة أو تعديلها؛ الانتظار القصير ليس حلاً مضموناً.» لا يُستنتج استنفاد الحصة اليومية من HTTP 429 وحده. يُمرّر `Retry-After` المورّد إذا كان عدداً أو تاريخ HTTP صالح الصيغة؛ لا تُختلق مدة عند عدم توفره.

لا تُعاد تفاصيل الاستثناءات أو المدخلات المرفوضة أو مفاتيح API أو مسارات النظام الداخلية. طلبات CORS مسموحة فقط من `CORS_ORIGINS`، وللطريقتين GET وPOST ورأس `Content-Type`؛ يمكن للواجهة قراءة `X-Request-ID` و`Retry-After`.

رد المزوّد الفارغ أو المبتور يعيد 502 `LLM_UNAVAILABLE`، وأخطاء 429/الاتصال/المهلة تبقى أخطاء HTTP ولا تتحول إلى `insufficient_evidence`. المتحقق يوحد تنسيق علامات المصادر مع بقاء تطابق المعرفات إلزامياً، ويقبل أرقام مجموعات الساعات من المصدر المستشهد به؛ لا يستخدم بيانات التعارض لإسناد ادعاء إلى مستند آخر. رموز رفض التحقق داخلية مرتبطة بمعرّف الطلب، ولا تسجل المطالبات أو خرج النموذج الخام.
